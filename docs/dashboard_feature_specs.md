# Спецификации функций визуализации

Документ описывает ключевые инициативы по развитию интерфейса аналитики. Каждая функция
получила примерную оценку по сложности (★) и размеру команды (S/M/L). Указаны сценарии
использования, требования к UX и зависимости.

## Конструктор дашбордов — ★★★, команда M

**Цель.** Пользователь без навыков кодирования быстро собирает интерактивную панель. Решение
должно поддерживать разные типы виджетов и работу с фильтрами на уровне всего дашборда.

**Основные возможности.**

- Drag-and-drop размещение карт, таблиц, текстовых блоков и KPI.
- Глобальные фильтры с наследованием на виджеты, отдельные локальные фильтры приоритетнее.
- Drill-through: переход из карточки в детальный отчёт с передачей контекста фильтров.
- Пресеты макетов (сеточная/свободная раскладка), снаппинг по колонкам.
- Автосохранение черновиков, версия дашборда и журнал изменений.

**UX/технические требования.**

- Обновление данных без полного перерендера (websocket/polling в зависимости от типа виджета).
- Ролевые права: создание/редактирование/просмотр, поддержка совместной работы.
- Конструктор должен поддерживать responsive-разметку для десктопов и планшетов.
- Бэкенд-API для CRUD операций по дашбордам, виджетам и связям между ними.

**Зависимости.** Завершение миграции на Postgres + Alembic (см. Q3 Roadmap), единая модель прав
доступа, готовый каталог метрик.

## Шаблоны графиков — ★★, команда S/M

**Цель.** Сократить время на создание типовых визуализаций и обеспечить единый дизайн.

**Основные возможности.**

- Набор пресетов: line, bar, pie, table, heatmap, комбинированные.
- Preview перед сохранением, автоматическое оформление (цвета, легенды, подписи осей).
- Привязка к бизнес-метрикам (подсказки по рекомендуемым визуализациям).
- Импорт/экспорт настроек графика в JSON для повторного использования.

**UX/технические требования.**

- Библиотека визуализаций (например, ECharts/Chart.js) с обёрткой для единых тем и доступности.
- Встроенная документация по выбору типа графика в тултипах и onboarding-подсказках.
- Кэширование метаданных и результатов запросов для ускорения отрисовки.

**Зависимости.** Каталог метрик, единая система тем и токенов дизайна, компонентная библиотека.

## Сравнение версий наборов данных — ★★, команда M

**Цель.** Позволить аналитикам отслеживать изменения в источниках: добавленные строки, изменения
метрик, актуальность схем.

**Основные возможности.**

- Дифф по строкам: подсветка добавленных, изменённых, удалённых записей.
- Дифф по агрегированным метрикам (средние, суммы, процентили) с отображением дельт.
- Автоматические заметки «что поменялось» с генерацией резюме.
- История версий с возможностью отката/экспорта изменений.

**UX/технические требования.**

- Планировщик задач, который формирует снимки данных и метаданных.
- Хранилище версий (S3/Postgres) с дедупликацией и сжатием.
- Бэкенд-API для запроса диффов и генерации отчётов (JSON/CSV/визуальный UI).
- Журнал аудита с автором изменений и временем.

**Зависимости.** Очередь задач и кэши (см. Q3 Roadmap), готовая модель метрик, нотификации.
