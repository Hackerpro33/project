# 0002 — Хранилище файлов и обработка очередей

## Контекст

Пользователи загружают тяжёлые CSV/XLSX файлы, которые затем обрабатываются синхронно или
через очередь. Необходимо гарантировать: сохранность данных, защиту от повторов и устойчивость
при обработке больших файлов.

## Решение

- **Общее хранилище** — локальный каталог `backend/uploads/` (по умолчанию), который может быть
  заменён на S3-совместимое хранилище. Каждый файл сохраняется под UUID-префиксом, а метаданные
  регистрируются в in-memory реестре для быстрого доступа.
- **Ограничение загрузок** — лимит `MAX_UPLOAD_SIZE_MB` (по умолчанию 25 МБ) и whitelist
  расширений `.csv/.tsv/.xlsx/.xls`. Дополнительно вызывается ClamAV (если доступен) для проверки
  на вредоносное содержимое.
- **Idempotency** — заголовок `Idempotency-Key` кэшируется в памяти и предотвращает повторное
  создание ресурса при ретраях.
- **Асинхронная обработка** — очередь RQ/Redis, управляемая флагом `TASK_QUEUE_ENABLED`. Маршрут
  `/api/v1/extract/async` ставит задачу, а `/api/v1/tasks/{task_id}` возвращает прогресс.

## Статус

Accepted — реализация присутствует в `backend/app/main.py`, `backend/app/tasks.py` и
сопутствующих тестах.

## Последствия

- Переключение на внешние хранилища требует конфигурации переменных окружения, но интерфейс API
  остаётся неизменным.
- Для горизонтального масштабирования требуется вынести реестр файлов в Redis/БД.
- Снимок OpenAPI фиксирует контракт `/api/v1`, что упрощает эволюцию версий API.
